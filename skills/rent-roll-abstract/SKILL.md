Use this skill when the user asked for unit counts, occupancy, vacant, MTM, or in-place income — including when the same message also asks locate/map. Ignore it only for a locate/map question with no count/occupancy/income ask. Buy / worth / value asks use underwriting — do not refuse them. Cite span_ids. Do not invent rents. Do not geocode or web-search on a pure abstract. Never copy `(skill)` into the user-facing sentence.
`in_place_monthly` is occupied-only. If all occupied / 100% occupancy / fill-vacancy income is a different question — call `compute_income` and cite `estimated_full_occupancy_monthly`; do not repeat occupied in-place. Follow-ups must answer the last user message (including “but this is the same as with vacancy”).
One unfiltered `query_units` JSON returns `unit_count`, `occupied_count`, `vacant_count`, `occupancy_pct`, and `mtm_count` (units on month-to-month leases) plus a note that those headline counts are complete in that result. If several checklist intents are headline counts (units, occupancy, vacant, mtm_count), that is ONE unfiltered `query_units` item, not four. After an unfiltered `query_units` has run this turn, do not call `query_units` again for those counts. Extra `query_units` only to LIST a filtered subset of unit rows, not to re-fetch counts. `compute_income` still for in-place monthly $. `compute_income` JSON also includes `mtm_count`. Use counts for existence/yes-no. `query_units` filters unit occupancy status only (Occupied/Vacant/all).
Always `create_plan` once first listing every distinct ask in the user message as **separate numbered lines** (map + vacant is two items: `1. osm_geocode` and `2. query_units` — never one comma-joined line). Never call `query_units` (or any work tool) unless it is already on the checklist — if you omitted it, `update_plan` with the new remaining work first. Then the `[in_progress]` work tool, then `update_plan_status`, then the next pending tool. Never skip `create_plan` on in-scope CRE. After `update_plan_status`, if any item is `[pending]` or `[in_progress]` and that tool has not run yet, call that work tool — not `update_plan_status` again. If a tool cannot supply the asked result, mark that item `[incomplete]` (terminal, like `[completed]` but without an answer) and do not retry it. Forbidden: `update_plan_status` → `update_plan_status` except to mark `[completed]`/`[incomplete]` a tool that already ran this run. If remaining items are `[completed]` or `[incomplete]`, Next: `score_gcr` then answer. If `score_gcr` says need_replan because the steps are wrong, call `update_plan` with the NEW remaining work only (never a second `create_plan`). `[completed]` / `[incomplete]` rows stay on the plan.
Forbidden: text-only `end_turn` on a CRE/rent-roll answer with no `score_gcr`. You MUST call `score_gcr(draft)` with the prose sentence you would show before you stop. Do not require RollAbstract JSON. If min(G,C)<=2, need_replan / more vault tools then `score_gcr` again. `vault_calc` N/A (number not in the vault allowlist, including derived math) is not a fail. Do not return to the user until G/C are ok or you hit the turn limit.
